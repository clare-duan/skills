# 提醒推送参考（Reminder Setup）

> 解决的问题：行程里"定了的事"和"要办的事"，不能靠人翻文档记住。决策时刻管"定"，推送管"到"——**躺在文档里的决定等于没做**。

## 三条原则（工具无关）

1. **次日版本晚间推送**：每晚决策时刻（如 20:00）定好次日走哪个版本后，当晚就推送到每个执行人眼前——第二天早上不用再对齐。
2. **死线待办单独建提醒**：退订截止、预约窗口、必打电话这类带死线的事，一条一个提醒；**提醒时间设在死线之前、留足操作余地**（例：18:00 截止的退订，提醒设 10:30）。标题写清后果，一眼知道不办会怎样，格式参考：`【死线】XX 免费取消截止——今天不退就退不掉了`。
3. **推给用得上的人**：只推给实际会看这个工具的人；同行人不用该工具的（比如长辈不用办公软件），对他们口头同步，别为了推送逼人装 App。

## 让 AI 帮你省掉手工设置

排完行程后，让 AI 顺手输出一份**提醒清单**（每条：标题＋触发时间＋一句后果），你往自己的工具里照抄即可。如果你的 AI 环境能直接操作日历（命令行工具、日历 API 或相应插件），可以让它直接代建——本方法论作者的用法就是口头说一句，AI 通过飞书的命令行工具（lark-cli）直接把日程建进飞书日历。

## 飞书参考实现（作者实战验证过的配置）

- **用哪个功能**：飞书日历的"日程"＋自带提醒（不是任务清单、不是群机器人）。
- **怎么建**：手动建即可——飞书日历新建日程，标题按上面第 2 条的格式写，设好提醒时间；或让能操作飞书的 AI 代建。
- **推给谁**：日程只加自己时就只提醒自己；要提醒同行人就把对方加为日程参与人（对方需有飞书）。

## 其他工具类比

| 你的工具 | 对应做法 |
|---|---|
| 手机自带日历/提醒事项 | 新建日程＋提醒，标题同上格式 |
| 微信 | 群里发"次日版本"＋用"提醒"功能或定时消息 |
| 钉钉 | 日程/待办＋提醒 |
| 闹钟 | 死线类最朴素兜底：闹钟标签写上后果 |

机制一样，换壳而已：**标题带后果、时间在死线前、推到人眼前。**
